# When a run stops

What a stopped `/build-feature` run looks like, what it means and who does what next. Every row is a case that happened: the greeting run on the rehearsal clone (2026-11-03, one note, three runs) or the stamps rehearsal (2026-11-04, three notes, four runs). The version 2 README's "When something stops" part starts from this table.

Where to look first: `changes/<name>/report.md` on the feature branch (`State:`, the notes table, `## Final check`), then the report the row names under `.git/build-feature/<name>/`, then the Workflow task panel.

| What you see | What it means | What you do | Who |
| --- | --- | --- | --- |
| A note row reads `failed`, 3 strikes, and `Last report` names a reviewer or verifier report | Three attempts were rejected. The run did not merge and the final check did not run. | Type `/build-feature <name>`. The short interview shows the last reject and offers two roads: change the note, or cut it. A cut deletes the note's tests too, and reverts its merge if it had one. | the human, at the keyboard |
| A note row reads `stopped: done check passes before the work`, or `stopped:` with an implementer's or the note checker's reason | The note needs an answer of the human's kind. The question is under Decide in `~/.claude/pending.md`. | Answer the question, then `/build-feature <name>`: the short interview opens on the row. | the human |
| A note row reads `stopped: worktree:` and the merger's report says the classifier denied `git worktree remove` | A fresh retry needed the old worktree gone, and an agent may not remove one. | Remove it from the session (`git worktree remove --force`, `git branch -D`, `git worktree prune`), then start again. Step 2 of the run does this for every `fresh` note. | The session |
| A note row reads `stopped: API errors` or `stopped: <role> returned no result`; `halted` names the role | An agent returned nothing twice: a usage limit the runtime stopped waiting for, or an outage. | Wait for the reset the task panel names, then start again; an outage names none, so wait 30 minutes, then start again. The report skips the merged notes. Three starts with no new merged note end the session; a start in which no agent answered at all does not count, so an outage ends the session only at the three-day limit (the human, 2026-11-04). | The session |
| `State: stopped` and `## Final check` ends on `FINDINGS` after a fix round | The one fix round did not clear the final check. Twice on the clone the fix round itself added a rule no note names (a budget test, a tables guard), and the final reviewer refused it; since 2026-11-04 the pre-commit hook refuses such a test file on the feature branch, so the fix round's commit fails instead and the implementer answers `stopped`. | Fix it on the feature branch in a session of its own (often: delete the extra file), commit, then start again: the final check and the merge run again, about 50 minutes on the clone. | A session, with the human for anything beyond a deletion |
| `## Final check` holds `On main:` lines | Faults that hold on local main too: red specs, baselines that differ, a table without RLS. Not the feature's, and never a ground. Since 2026-11-04 `lib/on_main.py` writes them: it runs the failed command here and on main and compares the failing tests by name, so no verifier decides. | Nothing for this run. Fix main in its own session when it matters. | the human decides |
| The final reviewer's report says the session answered its own question | An `Answer:` on the plan was written by the session, not by the human. The reviewer refuses the run on it, every time. | the human writes the answer in his words, the session appends a new `Approved:` line, commits, starts again. | the human |
| A row reads `merged` and its `Last report` is a REJECT | The script read the verdict wrong (fixed 2026-11-04: every role answers in a typed form the runtime checks, so a verdict cannot be misread from prose). | Stop the task. On the feature branch `git revert -m 1 <merge commit>`, set the row to `failed`, commit, then the short interview. | The session |
| `REFUSED: changed after the approval` names a note or a test of a note that has not merged | The plan or a note changed after the human approved it. A merged note's done-check edit no longer counts (fixed 2026-11-04). | the human reads the change and approves again, which writes a new `Approved:` line. | the human |
| `REFUSED:` names a `Waits for:` that points at a note that is gone | A cut note had dependants. | In the short interview, change each dependant's `Waits for:` or cut it too. | the human |
| A verifier REJECT on step 5 shows the same pixel count at the base commit | The committed baselines do not match this machine's render; the note touched no screen. `lib/on_main.py --twice` reruns the screen and runs it at the base, and the verifier passes the step on its `on main:` line. | Nothing for the run. If it keeps rejecting, retake the baselines on main in a session and commit them. | The session |
| The red check refuses "no new test title" | The note's done-check tests were committed at the interview, so the branch adds no new title. | Nothing. The implementer adds a `keeps:` test or a placement test; the report lists it under Defaults taken. | Nobody |
| The red check refuses a fix round that only strengthened a test | A stronger test passes on the pre-fix code, and the red check reads that as weak. | Nothing. The implementer labels it `keeps:`; the final reviewer reads it. A red check that takes a strengthened test is a later change to `suite.py`. | Nobody |
| A reviewer REJECT says a rights test proves nothing because local Postgres grants a new table nothing | A revoke test that reads the table as migrated here cannot go red. The repo's shape grants Supabase's defaults back in a rolled-back transaction and runs the rights block again. | Nothing at strike one. At strike two the note checker corrects the test inside what the human approved. | The note checker |
| The final verifier's report says the full suite is over budget | A line under `## Time`, not a finding, by the human's ruling of 2026-11-03 for the clone. | For Orderflow: the first interview asks the pruning question; the human answers it once. | the human |
| Nothing moved for 30 minutes: the report and the transcripts have the same change time | An agent hung, or the runtime is waiting on something it does not say. | The watchdog stops the task, sends the last transcript line to the phone and starts again. | The session |
| The Workflow tool refuses `scriptPath` | The script must be a file the session may already read. `Read(~/.claude/skills/**)` is in the human's settings since 2026-11-04, so this should not show. | If it still shows: `mcp__ccd_directory__request_directory` on `~/.claude/skills/workflow/skills/build-feature`, then start again; if that fails too, start from the skills repo and tell the human the rule did not hold. | The session |
| The report on main says `State: running`, or lacks the final check | The merge carried an old report (fixed 2026-11-04: the final report is written before the merge). | Copy the feature branch's report onto main and commit it as `report: <name> merged`. | The session |
| After the run, `git status` in the feature worktree shows retaken baselines or `changes/<name>/screens.md` uncommitted | The merger's baselines job did not run (fixed 2026-11-04: it runs after every final verifier). | Commit them as `baselines: <screens>` and start again. Removing the worktree loses them. | The session |
| The e2e global setup fails on a migration the branch does not have | The tree's claimed database still holds a cut note's migration. | Drop the batch's databases (`node scripts/run-db.mjs drop --batch <id>`) before the restart; a fresh claim rebuilds from empty. | The session |
| The final check fails on a test of a cut note | The revert of the note's merge restored the test the interview committed with it. | Delete the note's test files in the cut (the short interview does this since 2026-11-04), commit, start again. | the human's short interview |
| No notice on the phone though the result said "Mobile push requested" | The push left the app; the phone side is Remote Control's. | Check the app's notifications. Nothing to fix in the run. | the human |

Costs seen on the clone, for the budget: a one-note feature, three runs, $14.45; a three-note feature with one cut, four runs, 50 agents, $19.52 and about three hours, of which the final check was $13.74. The final check runs the clone's whole suite (400 to 540 s), every end-to-end spec (675 s) and the gate, so each pass is 30 to 75 minutes; the levers are a green main and the pruning answer, not the workflow.
