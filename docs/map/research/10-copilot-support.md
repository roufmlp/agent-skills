# Research: whether GitHub Copilot can run the same workflow

Sources checked: 2026-10-30

Order in every answer: desktop app, VS Code, Visual Studio 2026 (18.x) and 2022 (17.x), then Copilot CLI (the app's engine). Dropped: JetBrains, Eclipse, Xcode, cloud agent. Developer facts: Windows office PC, no .exe installs, skill files allowed.
Method: GitHub docs read from github/docs main (publishes docs.github.com), spot-checked on the live site. "App log" = https://github.com/github/app/blob/main/changelog.md , "CLI log" = https://github.com/github/copilot-cli/blob/main/changelog.md . "confirmed" = a page states it; "not confirmed" = no page states it.

## Q1. What is "the GitHub Copilot desktop app"? Which surfaces run agent sessions on a desktop?
- Answer: "the GitHub Copilot app". GitHub's page https://github.com/features/copilot headlines it "GitHub Copilot Desktop App". Standalone desktop app, technical preview since 2026-05-14, macOS, Windows, Linux, "built on GitHub Copilot CLI", latest release v1.1.33 (2026-10-27). Confirmed. https://docs.github.com/en/copilot/concepts/copilot-surfaces/github-copilot-app , https://github.blog/changelog/2026-05-14-github-copilot-app-is-now-available-in-technical-preview/ , https://github.com/github/app/releases
- Windows installer: the docs download links resolve to `GitHub-Copilot-windows-x64-setup.exe` (and `-arm64-setup.exe`); each release also ships `GitHub-Copilot-windows-x64.msi`. No portable zip for Windows. Observed from the link redirect and the release asset list, not from prose. The app updates itself on Windows by starting an installer (app log v1.1.11); fit with the employer rule: not confirmed. https://docs.github.com/en/copilot/get-started/quickstart-copilot-app
- Other desktop surfaces: VS Code (chat view plus a separate "Agents window", `code --agents`), Visual Studio 2026 and 2022, Copilot CLI (JetBrains too). Not the same product: "Copilot in GitHub Desktop". Confirmed. https://code.visualstudio.com/docs/agents/run/agents-window , https://docs.github.com/en/copilot/reference/customization-cheat-sheet

## Q2. Agent Skills: folders, frontmatter, slash invocation
- Desktop app: yes. It auto-loads skills set up for repos and for Copilot CLI: project `.github/skills/`, `.claude/skills/`, `.agents/skills/`; personal `~/.copilot/skills/`, `~/.agents/skills/`. Confirmed. https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app , https://docs.github.com/en/copilot/concepts/customizations/agent-skills
- App and `~/.claude/skills/`: not in GitHub's list, and the CLI stopped loading `~/.claude/` agents, skills and commands in v1.0.36 (2026-04-24). Repo `.claude/skills/`: confirmed. App-specific statement on `~/.claude/`: not confirmed. https://github.com/github/copilot-cli/blob/main/changelog.md
- App install and slash: Customize > Add > Install skill... takes a folder, ZIP, GitHub skill-folder URL or HTTPS ZIP, with a review step (app log v1.1.30). Skills appear in the `/` picker (app log v1.1.31); `/skills` and `/skills reload` exist. Confirmed. https://docs.github.com/en/copilot/reference/github-copilot-app-reference/slash-commands
- App frontmatter: no app list. The CLI list is name, description, argument-hint, allowed-tools, user-invocable (default true), disable-model-invocation (default false). App behaviour for each: not confirmed. https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#skills-reference
- VS Code: yes (`chat.useAgentSkills` default true). Docs say start with the Copilot harness (the runtime shared with the app and CLI); Local is an opt-in. Copilot harness `.github/skills/` and `~/.copilot/skills/` (a `.claude/skills/` read there: not confirmed); Local sessions also read `.claude/skills/`, `.agents/skills/`, `~/.claude/skills/`, `~/.agents/skills/`. Fields: name (must equal folder name), description, argument-hint, user-invocable, disable-model-invocation, context: fork. `allowed-tools` not listed (not confirmed). `/skill-name` works. Confirmed. https://code.visualstudio.com/docs/agent-customization/agent-skills
- Visual Studio 2026 (18.5+): yes. `.github/skills/`, `.claude/skills/`, `.agents/skills/`, `~/.copilot/skills/`, `~/.claude/skills/`, `~/.agents/skills/`. Fields listed: name, description, license, compatibility, metadata, allowed-tools. `disable-model-invocation` and slash invocation: not stated. Visual Studio 2022 (17.14): no skills. Confirmed. https://learn.microsoft.com/en-us/visualstudio/ide/copilot-agent-skills , https://docs.github.com/en/copilot/reference/copilot-feature-matrix

## Q3. Custom agents and subagents
- Desktop app: yes. Agent picker or `/agent`. Format: Markdown `.agent.md` (or `.md`) with YAML frontmatter; folders `.github/agents/` and user `~/.copilot/agents/` (CLI page; no app page lists a folder, so app folders: not confirmed); the CLI also finds `.claude/agents/` (CLI log v1.0.62). https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app , https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/create-custom-agents-for-cli
- Subagent: yes. "When the main agent delegates work to a custom agent, that work is carried out by a subagent with its own context window." Fields: name, description (required), tools, model, disable-model-invocation, user-invocable, mcp-servers, target. Tool aliases accept Claude names (Bash, Read, Edit, Write, Grep, Glob, Task); unknown tools are ignored; Claude `model:` aliases: not confirmed. The app shows sub-agents as tabs (app log v1.1.28) and needs approval for subagent plans (v1.1.24). A skill starting an agent by itself: not confirmed (a skill's text goes into the main agent's context). https://docs.github.com/en/copilot/reference/custom-agents-configuration
- VS Code: `.github/agents/*.agent.md` or `.md`; `.claude/agents/*.md` (Claude agent format); user `~/.copilot/agents`, `~/.claude/agents` (Claude harness). The Copilot harness delegates with its `task` tool; `agents:` frontmatter limits callable subagents; a skill with `context: fork` runs in a subagent. Confirmed. https://code.visualstudio.com/docs/agent-customization/custom-agents , https://code.visualstudio.com/docs/agents/run/subagents
- Visual Studio 2026 (18.4+): `.github/agents/*.agent.md`, user `%USERPROFILE%\.github\agents`; fields name, description, model, tools (Visual Studio tool names such as `code_search`); call with `@name`. Subagents: not supported (GitHub matrix). 2022: built-in agents only. Confirmed. https://learn.microsoft.com/en-us/visualstudio/ide/copilot-specialized-agents

## Q4. Hooks that refuse a tool call
- Desktop app: yes. "Repository hooks and hooks supplied by plugins"; VS Code, the app and the CLI share one Copilot harness and hook format. The app makes you review and accept repository hooks first (app log v1.1.27, v1.1.29). User-level hook files in the app: not confirmed. https://docs.github.com/en/copilot/concepts/customizations/hooks , https://code.visualstudio.com/docs/agent-customization/hooks
- Config: JSON `{"version":1,"hooks":{"preToolUse":[{"type":"command","bash":"...","powershell":"...","cwd":"...","env":{},"timeoutSec":30}]}}` in `.github/hooks/*.json`; user `~/.copilot/hooks/*.json`; inline `hooks` in `.github/copilot/settings.json`, `~/.copilot/settings.json` and `.claude/settings.json`; plugins ship `hooks.json` or `hooks/hooks.json`. Confirmed. https://docs.github.com/en/copilot/reference/hooks-reference
- Refuse: yes. `preToolUse` prints top-level `{"permissionDecision":"deny","permissionDecisionReason":"..."}` or exits 2. A crash or other non-zero exit also denies (fail-closed); a timeout lets the call run (fail-open). Confirmed. Same page.
- Input: camelCase `preToolUse` gets `{sessionId, timestamp(ms), cwd, toolName, toolArgs}`. PascalCase `PreToolUse` gets Claude-style `{hook_event_name, session_id, timestamp(ISO), cwd, tool_name, tool_input}` with Claude names (`Bash`, `Read`, `Write`, `Edit`, `Grep`, `Glob`, `WebFetch`, `Agent` for `task`). Runtime names: `bash`, `powershell`, `view`, `create`, `edit`, `grep`, `glob`, `web_fetch`, `task`. Confirmed. Same page.
- Not identical to Claude Code: nested `hookSpecificOutput.permissionDecision` is not the documented Copilot output (use top-level fields or exit 2); `tool_use_id` and `transcript_path` are not guaranteed. Confirmed. https://code.visualstudio.com/docs/agent-customization/migrate-customizations#migrate-hooks
- VS Code: hooks are Preview, Copilot harness only. Visual Studio 2026 and 2022: no hooks (GitHub matrix: not supported; Learn pages do not mention them). Confirmed. https://docs.github.com/en/copilot/reference/customization-cheat-sheet

## Q5. Plugins and marketplaces from a GitHub repo
- Desktop app: yes. Customize > marketplace settings > add "the GitHub repository or Git URL that hosts the marketplace" > Browse > Install; a "From your organization" tab shows managed marketplaces. Plugins can carry skills, hooks, custom agents, MCP servers, canvases. Confirmed. https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app
- Claude format: CLI and VS Code accept `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` (marketplace manifest order: `marketplace.json`, `.plugin/`, `.github/plugin/`, `.claude-plugin/`); Claude-style `agents/`, `skills/`, `hooks/hooks.json`, `.mcp.json` load as a legacy plugin. App formats: not confirmed (no app page). https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference , https://code.visualstudio.com/docs/agent-customization/agent-plugins
- CLI commands: `copilot plugin marketplace add OWNER/REPO` (also `OWNER/REPO#ref`, Git URL), `copilot plugin install PLUGIN@MARKETPLACE`, `copilot plugin install OWNER/REPO`, `copilot plugin update --all`, `copilot plugin marketplace update`; `/plugin ...` in a session. https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/plugins-finding-installing
- Auto-update: the app has an option "update installed plugins and their extensions automatically" in Customize > Plugins (app log v1.1.10) and "update all" (v1.1.9); its default: not confirmed. CLI: only first-party plugins, or a marketplace with `autoUpdate: true` in user `extraKnownMarketplaces`, at session start; repo-level `autoUpdate` is ignored. VS Code: `extensions.autoUpdate` (npm/PyPI plugins never) or "Chat: Update Plugins". https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference
- VS Code install: Agent Customizations > Plugins > + (Git URL), or "Chat: Install Plugin from Source"; marketplaces in `chat.plugins.marketplaces` (Experimental, `owner/repo`; defaults `github/copilot-plugins`, `github/awesome-copilot`). Plugin support is off unless `chat.plugins.enabled` is true (reference default: false). Visual Studio 2026 and 2022: no plugin pages found (not confirmed). https://code.visualstudio.com/docs/agent-customization/agent-plugins

## Q6. Instruction files
- Desktop app: global instructions in Settings > Sessions > "App instructions" (no file path); per-repo "Instructions" field or `instructions:` in `.github/github-app.yml` (legacy `.github/copilot-desktop.yml`), applied after the global ones. App log v0.2.15 mentions AGENTS.md and CLAUDE.md guidance (not a docs page); `.github/copilot-instructions.md` for the app: not confirmed. https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app , https://docs.github.com/en/copilot/reference/github-copilot-app-reference/repository-configuration
- Copilot CLI (engine): `.github/copilot-instructions.md`, `.github/instructions/**/*.instructions.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, personal `~/.copilot/copilot-instructions.md` and `~/.copilot/instructions/`; `.claude/rules` (CLI log v1.0.89). https://docs.github.com/en/copilot/reference/custom-instructions-support
- VS Code: Copilot harness `.github/copilot-instructions.md` or `AGENTS.md`, plus path-specific files; `CLAUDE.md` is listed for the Claude harness only. https://code.visualstudio.com/docs/agent-customization/custom-instructions
- Visual Studio 2026/2022: `.github/copilot-instructions.md` (switch on in Tools > Options), `.github/instructions/*.instructions.md`; user file `%USERPROFILE%/copilot-instructions.md` (2026). AGENTS.md and CLAUDE.md: not stated. https://learn.microsoft.com/en-us/visualstudio/ide/copilot-chat-context

## Q7. Office controls (Copilot Business and Enterprise)
- Desktop app: its own "GitHub Copilot app" policy (default on); turning off the Copilot CLI policy does not turn off the app. "MCP servers in Copilot" and the MCP registry allowlist apply to the app. Confirmed. https://docs.github.com/en/copilot/how-tos/copilot-cli/administer-copilot-cli-for-your-enterprise , https://docs.github.com/en/copilot/reference/supported-surfaces-for-policies
- Skills, custom agents, hooks: no GitHub policy that switches off only these was found in the policy tables (not confirmed). Control comes from managed settings (next line) and VS Code device policies. https://docs.github.com/en/copilot/concepts/enterprise/policies
- Plugins from an outside repo: yes, an admin can block them. Enterprise `managed-settings.json` keys: `strictKnownMarketplaces` (only listed marketplaces, `[]` = lockdown, built-ins off), `enabledPlugins` (require or block `plugin@marketplace`), `extraKnownMarketplaces` (add; optional `autoUpdate`). Supported by the app, VS Code, CLI. Delivery: server (org with a `.github-private` repo), MDM (Intune, Jamf) or file (Windows `%ProgramFiles%\GitHubCopilot\managed-settings.json`, registry `HKLM\SOFTWARE\Policies\GitHubCopilot`). Business org without an enterprise: not confirmed. https://docs.github.com/en/copilot/reference/enterprise-administrators/enterprise-managed-settings , https://docs.github.com/en/copilot/how-tos/administer-copilot/manage-for-enterprise/use-managed-settings/manage-plugin-marketplaces-and-plugins
- Hooks and MCP: admin policy hooks (`C:\ProgramData\GitHub\Copilot\policy.d\*.json`) load first and `disableAllHooks` cannot turn them off (CLI); `allowedMcpServers` and `deniedMcpServers` in managed settings. https://docs.github.com/en/copilot/reference/hooks-reference
- VS Code device policies (Group Policy, Intune): `ChatAgentMode`, `ChatHooks` (Local harness only), `ChatAllowManagedHooksOnly`, `ChatStrictPluginOnlyCustomization` (blocks standalone user and workspace skills, agents, instructions, MCP servers), `ChatEnabledPlugins`, `ChatExtraMarketplaces`, `ChatStrictMarketplaces`, `ChatMCP`. https://code.visualstudio.com/docs/enterprise/manage-ai-settings
- Visual Studio: GitHub-side IDE policies apply (chat, agent mode, MCP); a Visual Studio device policy for skills, agents or plugins: not confirmed. https://docs.github.com/en/copilot/reference/enterprise-administrators/policy-conflicts

## Q9. (A) Desktop app on Windows: folders read
GitHub writes `~`. For hooks it names the Windows form `%USERPROFILE%\.copilot\hooks\`; `~` is the same home folder for the rest. `COPILOT_HOME` moves `.copilot`. App pages list no paths; the app says it reuses CLI skills and MCP, and shares the CLI hook format.
- Skills: repo `.github\skills\`, `.claude\skills\`, `.agents\skills\`; personal `%USERPROFILE%\.copilot\skills\`, `%USERPROFILE%\.agents\skills\`. Not read: `%USERPROFILE%\.claude\skills\` (CLI since v1.0.36; app: not confirmed).
- Custom agents: repo `.github\agents\` (CLI also `.claude\agents\`); personal `%USERPROFILE%\.copilot\agents\`.
- Hooks: repo `.github\hooks\*.json`; personal `%USERPROFILE%\.copilot\hooks\*.json`; inline `hooks` in `.github\copilot\settings.json`, `%USERPROFILE%\.copilot\settings.json`, `.claude\settings.json`; admin `C:\ProgramData\GitHub\Copilot\policy.d\*.json`.
- Instructions: Settings UI plus `.github\github-app.yml`; CLI files `%USERPROFILE%\.copilot\copilot-instructions.md`, `%USERPROFILE%\.copilot\instructions\`, repo `AGENTS.md`, `CLAUDE.md`, `.github\copilot-instructions.md`.
- Plugins: `%USERPROFILE%\.copilot\installed-plugins\<marketplace>\<plugin>\`; cache `%LOCALAPPDATA%\copilot`. Whether the app (not the CLI) uses `.copilot` for every item: not confirmed.
- One personal skills folder read by the app, CLI, Visual Studio 2026 and VS Code Local: `%USERPROFILE%\.agents\skills\`.
- Sources: https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference , https://docs.github.com/en/copilot/reference/hooks-reference , https://code.visualstudio.com/docs/agent-customization/migrate-customizations

## Q10. (B) Hooks on Windows: what runs a command, bundled Node or Python, routes without an installer
- What runs: the `powershell` field is "Shell command for Windows"; `command` is copied to `bash` and `powershell` when those are absent; `bash` is "Shell command for Unix"; `exec` plus `args` starts an executable directly. `cmd.exe` is not mentioned. Which PowerShell runs a hook (7 or 5.1): not confirmed. The CLI shell prefers `pwsh` and falls back to `powershell.exe`; GitHub's Windows hook examples "require you to have PowerShell 7.0 or later". https://docs.github.com/en/copilot/reference/hooks-reference , https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks
- Bundled Node or Python for hooks: not confirmed. No page says the app or CLI exposes one. VS Code's hook example "requires Node.js on the execution host"; the CLI npm route needs Node.js 22+; the app bundles Git (app log v1.1.28). So a Python hook needs Python on PATH. https://code.visualstudio.com/docs/agent-customization/hooks , https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli
- Routes without a new install: (1) rewrite the four hooks as PowerShell in the `powershell` field (read JSON on stdin, exit 2 to refuse); (2) a `type: "http"` hook (HTTPS only) to a server you run, no local runtime; (3) app sessions in a WSL 2 distribution (WSL hosts on by default, app log v1.1.31), where hooks may run: not confirmed. https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions#running-sessions-in-wsl

## Q11. (C) Install a plugin or skill pack from GitHub with no .exe; self-update
- Yes, no installer step: Customize > add the marketplace (GitHub repo or Git URL) > Install; or Customize > Add > Install skill... from a GitHub skill-folder URL, ZIP, folder or HTTPS ZIP. The app needs Git (bundled, app log v1.1.28); nothing else is listed. Confirmed. https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app , https://docs.github.com/en/copilot/get-started/quickstart-copilot-app
- Self-update: plugins, as an opt-in option (app log v1.1.10); default and interval: not confirmed. A skill added by "Install skill..." is a copy; its update path: not confirmed. An app update once deleted user-added skills (fixed in app log v1.1.10). `gh skill update` and `copilot plugin update` need `gh` or the CLI, which are installers (docs: WinGet or npm).
- Repo default: `.github/copilot/settings.json` `enabledPlugins` plus `extraKnownMarketplaces`; the app's project settings list them (app log v1.1.31) and users can turn them off. Whether the app installs from it by itself: not confirmed.
- Caveat: the app's own Windows download is `-setup.exe`; an `.msi` exists. https://github.com/github/app/releases
